# Simple Vault — практика Anchor

Учебный контракт на Anchor 0.31.1 (Solana).

## Неделя 8 & 9: Каркас Vault, карточка пользователя, депозит и share-токены

В рамках недели 9 в контракт добавлена механика депозита базовых SPL-токенов с начислением пользователю долей (share-токенов).

---

### 1. Что такое PDA и Сиды

- **PDA (Program Derived Address)** — адреса без приватного ключа, вычисляемые из сидов и program id, лежащие вне кривой ed25519 и контролируемые программой.
- **Сиды хранилища (`vault_state`)**: `[b"vault", token_mint]`
- **Сиды карточки (`user_card`)**: `[b"user_card", vault, user]` (уникальная карточка на пару хранилище-пользователь).

---

### 2. Депозит и формула расчета долей (Shares)

Когда пользователь вносит токены в vault, взамен он получает share-токены (доли), которые служат подтверждением его права собственности на часть пула ликвидности.

#### Формула расчета:
1. **Первый депозит** (когда `total_shares == 0` или `total_tokens == 0`):
   ```
   shares = amount (соотношение 1:1)
   ```
   Первый вкладчик задаёт базовый масштаб пула: за 1 внесенный токен получает 1 share.

2. **Последующие депозиты**:
   ```
   shares = amount * total_shares / total_tokens
   ```
   Количество получаемых долей пропорционально вносимой сумме по отношению к текущей капитализации хранилища.

#### Почему поздний вкладчик получает меньше shares при наличии прибыли?
Если хранилище заработало прибыль (например, через комиссии, доходность yield farming или прямое пополнение пула), то `total_tokens` (баланс пула) становится больше, чем `total_shares`.
- В этот момент ценность 1 доли возрастает: `1 share = total_tokens / total_shares > 1 базового токена`.
- Следовательно, новый вкладчик, внося фиксированную сумму `amount`, покупает доли по более высокой цене и получает **меньше shares**, чем получил бы первый вкладчик на ту же сумму.
- Это абсолютно справедливо: накопленная прибыль принадлежит тем, кто держал свои средства в пуле ранее, а новые вкладчики не размывают прибыль первоначальных инвесторов.

---

### 3. Механизм CPI (Cross-Program Invocation) при депозите

Инструкция `deposit` выполняет два межпрограммных вызова (CPI) к SPL Token Program:

1. **Перевод токенов (Пользователь -> Vault)**:
   - Вызывается `token::transfer` через `CpiContext::new`.
   - Источник: `user_token_account`.
   - Получатель: `vault_token_account`.
   - Authority: сам пользователь (`user`), который подписывает транзакцию своим приватным ключом.

2. **Минт долей (Vault -> Пользователь)**:
   - Вызывается `token::mint_to` через `CpiContext::new_with_signer`.
   - Mint: `share_mint`.
   - Получатель: `user_share_account`.
   - Authority: `vault_state` (PDA).
   - Так как у PDA нет приватного ключа, среда Solana требует передать семена (`seeds = [b"vault", token_mint.as_ref(), &[bump]]`). Рантайм проверяет, что вызывающая программа владеет данным PDA, и временно наделяет вызов правами подписи.

3. **Обновление состояния**:
   - `vault.total_tokens += amount`
   - `vault.total_shares += shares`
   - `card.deposited += amount`
   - `card.shares += shares`

## Тестирование

```bash
yarn test
```

Тесты проверяют:
- Инициализацию vault и карточек пользователей.
- Первый депозит пользователя A (1:1).
- Второй депозит пользователя B с корректным начислением shares.
- Запрет депозита без предварительно созданной карточки (`create_user_card`).
- Запрет депозита нулевой суммы (`ZeroAmount`).
