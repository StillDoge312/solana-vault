# Simple Vault — практика Anchor

Учебный контракт на Anchor 0.31.1 (Solana).

## Неделя 8: Каркас Vault и карточка пользователя (User Card)

Контракт реализует базовую архитектуру хранилища ликвидности:
1. **Инициализация хранилища (`initialize_vault`)**: администратор создаёт vault для конкретного SPL-токена.
2. **Карточка пользователя (`create_user_card`)**: личный PDA-аккаунт пользователя внутри vault для отслеживания его депозитов и долей.

---

### Теория: Что такое PDA (Program Derived Address)?

**PDA (Program Derived Address)** — это специальные адреса в Solana, которые:
- **Не имеют соответствующего приватного ключа**: они детерминированно вычисляются с помощью функции хэширования `find_program_address` из набора байтовых строк (**seeds**) и публичного ключа программы (**program id**).
- **Лежат вне эллиптической кривой ed25519**: алгоритм подбирает дополнительный байт (**bump seed** от 255 вниз до 0), гарантируя, что точка не лежит на кривой, а значит, ни один человек или внешний кошелёк физически не может сгенерировать приватный ключ для этого адреса.
- **Полностью контролируются программой**: только та программа, чей `program id` использовался при вычислении адреса, имеет право изменять данные этого аккаунта, переводить с него SOL или подписывать от его имени транзакции (вызовы CPI) с помощью инструкции `invoke_signed` (в Anchor: `CpiContext::new_with_signer`).

PDA используются как безопасные хранилища данных программы (state) и как программные кошельки (escrow/vault), способные хранить токены и подписывать действия без риска утечки ключей.

### Архитектура аккаунтов и Сиды (Seeds)

#### 1. Сиды хранилища (Vault State):
`seeds = [b"vault", token_mint.key().as_ref()]`
- Хранит глобальное состояние пула: адрес администратора (`admin`), поддерживаемый SPL-токен (`token_mint`), адреса токен-аккаунта хранилища (`vault_token_account`) и mint-аккаунта долей (`share_mint`), общий объем токенов (`total_tokens`), общий объем выпущенных долей (`total_shares`) и `bump`.
- Детерминированность: для каждого уникального токена (`token_mint`) в системе может существовать ровно одно хранилище.

Связанные PDA:
- **Токен-аккаунт хранилища (`vault_token_account`)**: `seeds = [b"vault_tokens", token_mint.key().as_ref()]`, authority — `vault_state` PDA.
- **Mint долей (`share_mint`)**: `seeds = [b"share_mint", token_mint.key().as_ref()]`, mint authority — `vault_state` PDA (decimals: 6).

#### 2. Сиды карточки пользователя (User Card):
`seeds = [b"user_card", vault_state.key().as_ref(), user.key().as_ref()]`
- Хранит локальное состояние пользователя в данном vault: ссылку на хранилище (`vault`), владельца (`owner`), объем внесенных токенов (`deposited`), количество принадлежащих долей (`shares`) и `bump`.
- Детерминированность: сиды связывают конкретного пользователя с конкретным хранилищем. Попытка вызвать `create_user_card` повторно с теми же пирамидными сидами завершится ошибкой рантайма Solana (аккаунт уже инициализирован).

---

## Структура инструкций

```
initialize_vault    создаёт VaultState PDA, vault token account и share mint
create_user_card    создаёт UserCard PDA — личную карточку пользователя в vault
```

## Тестирование

```bash
yarn test
```

Тесты проверяют:
- Корректную инициализацию vault администратором.
- Создание личных карточек пользователями A и B.
- Невозможность создания повторной карточки для одного и того же пользователя.
